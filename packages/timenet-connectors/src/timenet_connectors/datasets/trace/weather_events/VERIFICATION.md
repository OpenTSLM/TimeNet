# Verification: `trace/weather-events`

Status is one of ✅ Done, ☑️ Done once, ⚠️ Open or ⚪ N/A, or a combination such as
✅ Done / ⚠️ Open. Every row needs evidence, and a ✅ Done row names its test or build check in
backticks. "Choosing a status" in `docs/connector-verification.md` gives the rules. When in doubt,
pick the weaker status.

Tests named below are in `tests/test_connector.py` unless stated otherwise. The ☑️ Done once checks
come from two kinds of pass, both over the archive pinned by `SOURCE_SHA256`, whose local copy
hashes to the pin:

- **Source passes, 2026-10-23 to 2026-10-25.** They compare the archive only with outside
  references: the `.npy` arrays, the Hugging Face release, GHCNh, the paper, and a model check. No
  connector code takes part, so they hold for this version. They ran for an earlier version of the
  connector, and their rows say "source pass".
- **Build passes, 2026-10-25, on this version.** Two full builds, a read-back of every value and
  timestamp against `json.load` of the archive, every task against the authors' code executed from
  source, and the leakage counts. Their rows say "build pass".

Neither pass is in the repo yet.

The leakage items (#44, #48, #50–#53) follow the connector's convention: metadata is never model
input, and an annotation is model input only for a task that names it in `input_annotations`. A
task's model input is then its Records' signals, cut to its `scope` when it has one, its named input
annotations and its prompt.

## References

The connector reads the Google Drive archive (sha256 `a5d24d75…be58`). Independent copies of the
same data, which it doesn't read:

- **The `.npy` arrays in the archive.** `pretrain/*_data/` and `classification/*_data/` hold one
  array per window, in the seven channels of `keys_to_save`, with `labels.npy`. Each
  `pretrain/*_data/` folder also has an `ids.txt` that names the window of every array, so these
  arrays can be matched by id. The `classification` arrays only have file order.
- **The `timeseries` column of `retrieval/*.parquet`.** It holds each described window's series as
  `.npy` bytes, keyed by `id`. The connector skips this column.
- **The Hugging Face release** at revision `3e02bda`: `mmts.jsonl` (44,565 described windows, keyed
  by `id`) and `event_report.jsonl` (4,855 events). The card calls `ts_dict_index` "line indices
  into `mmts.jsonl`", but the values are window ids. Read as ids, they give an independent
  event-to-window join.
- **The authors' code** at commit `1b65246` of TRACE-Multimodal-TSEncoder: `EVENT_MAP` in
  `src/common.py`; `keys_to_save`, `load_timeseries_from_json`, `load_forecasting_from_json`,
  `generate_dsp` and `generate_er` in `src/data/load_data.py`; `ForecastingDataset` in
  `src/data/dataset.py`; `forecast_finetune.py` and `configs/finetune.yaml`.
- **Upstream NOAA:** GHCN-hourly (GHCNh) by-year PSV files at each window's station, and the Storm
  Events fields (state, county, begin time) that `event_report.jsonl` carries.
- **The paper**, arXiv:2506.09114: Table 8 for the split sizes, Appendix B.5 for the label order,
  the total and the mean length, Tables 3, 5 and 8 for the forecast horizons. The only prompt in the paper
  (Appendix B.4) is the one the authors gave ChatGPT to write the descriptions.

## Fields

What every field of the source and of the authors' code becomes, then every value the connector
adds. "Window JSON" is `pretrain/*.json` and `forecasting/*.json`, and "retrieval" is
`retrieval/*.parquet`.

| Split file | The file a window comes from | Task split, `source_file` metadata | The authors' split files (#43) |
