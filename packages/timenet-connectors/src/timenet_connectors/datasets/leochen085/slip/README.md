# SLIP Pretraining Corpus

The corpus SLIP was pretrained on: sensor time-series with captions that a language model wrote. One
record is one row of one parquet shard. A row holds a series or a set of series, four captions of
them, and the name of the corpus they came from.

- **id**: `leochen085/slip`
- **source**: https://huggingface.co/datasets/LeoChen085/SlipDataset
- **licence**: MIT

MIT is what the release states. It covers what SLIP added: the packaging and the captions. The
corpora SLIP assembled it from keep their own terms, and this connector makes no claim about them.

## The source of truth

| fact | source of truth | the other reading |
| --- | --- | --- |
| the columns a shard holds | the shard: seven — `category`, `dataset`, `caption0`–`caption3` and `time_series` *(measured over all 17)* | `dataset_info.json`, which this build never fetches, so what it declares is unchecked here |
| how many rows the corpus holds | the shards: **618,508** *(measured)* | the card's domain table sums to 448,822, and its prose says "600K+" |
| how many values the corpus holds | the shards: **1,684,610,695** *(measured)* | the card says "approximately one billion" |
| the ratio of multivariate to univariate rows | the shards: **0.75 : 1** *(measured)* | the card says the two were sampled 2:1 |
| what the four caption columns hold | the values: four paraphrases of one caption *(measured)* | the card says "three levels of granularity — statistical, structural, and semantic" |
| which files the release ships | the repository: 17 `.parquet` shards | `state.json` names 17 `.arrow` files that do not exist |

The data wins in every row, for one reason. A reader can measure the data again. A reader cannot
measure a sentence. Every losing reading stays here rather than being deleted, because a reader who
arrives from the card must know why the numbers differ.

## What the description states

> This repository contains the data released alongside SLIP (Sensor Language-Informed Pretraining)
> [...] It includes two components: **(1)** the pretraining corpus of 600K+ paired sensor
> time-series and hierarchical text captions, and **(2)** 11 downstream evaluation datasets
> spanning four sensor domains.

Decides: the release is two datasets, and this connector is the first of them. The evaluation
folders have a different schema.

> Captions are generated at three levels of granularity — statistical, structural, and semantic —
> following the SensorLM recipe, with paraphrases generated by Qwen2-7B-IT to reduce template
> repetition.

Decides: nothing, because the values contradict it. Read "Four caption fields, three caption
levels".

> Qwen2-7B-IT generated three paraphrases per caption; one is randomly sampled during training.

Decides: `caption0` is the original, and `caption1` to `caption3` are its paraphrases. The values
agree with this sentence.

> Captions are automatically generated and paraphrased by language models, and may contain errors
> or hallucinations.

Decides: a caption is what the generator of SLIP wrote, not ground truth. Anyone who trains on these
must read them that way.

> This dataset should **not** be used for clinical decision-making. It is intended for research
> purposes only.

Decides: nothing in the conversion. It is repeated here because half the corpus is health data.

## What one record holds

One record is one row of one shard.

**Signals.** One `TimeSeries` per inner list of the row's `time_series` column. They are named `s0`,
`s1` and so on, in the order the row states. Every series in one row has the same length *(measured:
0 ragged rows)*. Lengths run from 64 to 96,424. The length is constant per source corpus for 31 of
the 37 corpora.

The corpus states **no unit for anything**, so every series is dimensionless. The values do have a
unit. The release does not say what it is.

**The time axis** comes from `meta.csv`, joined on the row's `dataset` column. The join is exact and
total. All 37 corpus names match a `meta.csv` row, and those rows cover every one of the 618,508
rows *(measured)*.

`meta.csv` states a `Freq` per corpus. Where that cell parses, the series gets a `RegularAxis` at
that period. Seven corpora state `Freq = "-"`: `BIDMC32HR`, `ChatTS`, `EigenWorms`, `Phoneme`,
`PigArtPressure`, `PigCVP` and `StarLightCurves`. Their rows get an `OrdinalAxis`, which records the
order and claims no wall-clock rate. That is **134,507 records**, and the other **484,001** carry a
real time axis *(measured)*.

**Annotations.** All of them are about the whole record. None is scoped to a signal.

| key | value | where it came from |
| --- | --- | --- |
| `source_dataset` | the corpus this row came from, for example `BIDMC32HR` | the `dataset` column |
| `domain` | for example `Health` | the `category` column |
| `source_url` | the paper or page for that corpus | `meta.csv`, through the join |
| `all_nan_signals` | which series holds no finite numbers | only on the 96 rows that need it |

`category` is redundant. It is a function of `dataset`, and it equals the `Domain` column of
`meta.csv` in all 37 cases *(measured)*. The connector keeps it because the release ships it.

**The record id is positional** — `slip-shard-00000-row-000000`. It holds a prefix, then the number
of the shard and the place of the row in it. The release ships no id of its own. None of the seven
columns of a shard identifies the row *(measured over all 17)*. Two builds of one release give the
same ids. A new release invalidates them.

## The tasks this connector builds

| the question | type | count | scope |
| --- | --- | --- | --- |
| given this row's series, write this caption | `AnswerTask`, no prompt | **2,474,032** *(measured: four per record)* | the whole record |

Four tasks per record, one per caption column, with the caption inline as the target.

The tasks are flat. Nothing records that `caption1` to `caption3` are rewrites of `caption0`. That
relation is real for most of the corpus and empty for the 105,085 `ChatTS` rows, whose four captions
are byte-identical. For a sixth of the release, that relation is true and says nothing.

The build streams the tasks rather than listing them. Two and a half million tasks is not a list.

## Inconsistencies and decisions

### The corpus is larger than the card's own table — **Handled**

**Problem.** The card says "600K+ sensor–caption pairs" in prose, and its domain table sums to
448,822. The shards hold **618,508 rows** *(measured over all 17)*. Every percentage in that table
is computed against 448,822, so the table agrees with itself and disagrees with both the prose and
the data. The card's "approximately one billion time points" is also low. The shards hold
**1,684,610,695** float values *(measured)*.

**Decision.** Convert every row. The manifest states 618,508, and this README states the
disagreement.

**Consequence.** A reader who compares against the table of the card finds a third more data than
expected. That is the release, not an error in the conversion.

### The shards ship no id of their own — **Handled**

**Problem.** Every shard holds the same seven columns: `category`, `dataset`, `caption0`–`caption3`
and `time_series` *(measured over all 17)*. None of them identifies the row, so nothing a build
reads can become a record id. A declared schema belongs in `dataset_info.json`. `download` never
fetches that file, so what it states is unchecked here.

**Decision.** Take the schema from the shards. Build the record id from the shard number and the row
position, and state here that it is positional.

**Consequence.** The ids are stable across builds of this release, and not across releases. A reader
who wants to trace a row back to its corpus has `source_dataset`, and nothing finer.

### Four caption fields, three caption levels — **Handled**

**Problem.** The card describes three levels of granularity: statistical, structural and semantic.
The schema declares four caption fields. The values are neither. In every sampled row, all four
captions state the same trend segments, the same cycle period, the same rounded statistics and the
same subject label. `caption1` to `caption3` are `caption0` rewritten in fluent prose *(measured)*.

**Decision.** Treat them as the other sentence of the card describes them, as one caption and three
paraphrases. Build one task per field.

**Consequence.** There is no way to ask this corpus for a statistical caption as distinct from a
semantic one. That distinction is not in the data.

### 105,085 rows have four identical captions — **Handled**

**Problem.** Every `ChatTS` row carries four byte-identical captions *(measured)*. The paraphraser
never ran on them.

**Decision.** Build four tasks anyway, as for every other row.

**Consequence.** A sixth of the corpus trains four times on the same string per record. A reader who
samples one caption at random per row is unaffected, and the card says the corpus was used that way.

### 216 captions are a paraphraser stub — **Handled**

**Problem.** 216 captions hold `Paraphrase 1:` or `The second paraphrase:` where the text must be
*(measured)*. The shortest `caption3` in the corpus is one character.

**Decision.** Convert them as they are. Warn once for the whole build, with the count.

**Consequence.** 216 tasks have a target that is not a caption. The warning makes them findable, and
they are what the release states.

### 123,098 captions stop mid-sentence — **Handled**

**Problem.** 123,098 of the 2,474,032 captions do not end in a sentence-ending character
*(measured)*. They stop where the generator hit a length limit, usually on a trailing comma:
`"…the readings has no trend,"`. Some stop mid-word: `"The 60-second tri-ax"`, `"Paraph"`, `"The"`.

**Decision.** Convert them as they are. Warn once for the whole build, with the count and one
example. One warning per caption says nothing that the count does not.

**Consequence.** One caption in twenty is an unfinished sentence. A model trained on these learns to
stop mid-sentence. A reader who wants this corpus for captioning must filter on a terminating
character.

### 253,587 captions carry a stray `￼` — **Handled**

**Problem.** U+FFFC, the object-replacement character, appears in 253,587 `caption0` values, 2,102
`caption2` values and 12 `caption3` values *(measured)*. It comes from the `Description` column of
`meta.csv`, where it is a document-paste artifact, and the caption generator copied it through.

**Decision.** Keep it, unchanged.

**Consequence.** 10% of captions carry a character that means nothing, and 41% of records hold at
least one. The affected records are exactly the `caption0` count, so every one of them carries it in
`caption0`. If the connector removed it, the conversion differs from the release and nothing says
why.

### 96 rows ship a series that is entirely NaN — **Handled**

**Problem.** 96 `dalia` rows each have exactly one of their six 388-point series entirely NaN
*(measured)*. No series is partly NaN, and the corpus holds no infinity. Nothing in the row marks
it, and the caption still describes all six series.

**Decision.** Build the series and keep every value. Warn once for the whole build, with the count.
Add an `all_nan_signals` annotation to each record that has one, naming which series it is.

A series that holds some numbers and some NaN warns too, separately. That warning names how many of
its values are not finite numbers. No row of this release trips it, so it is silent today. It is
what holds the paragraph above to its word. A release that starts to ship partial gaps says so,
rather than passing as clean.

Both counts ask whether a value is finite, so an infinity counts beside a NaN. The two warnings say
"finite numbers", because that is what they test. The `all_nan_signals` annotation does not. A
series of nothing but infinities carries it, and the name is then wrong about which non-number it
found. This release ships no infinity at all *(measured)*, so the name cannot mislead today.

**Consequence.** Those records carry a series with no numbers in it. That is a fact about the
corpus, and the annotation makes it findable without a scan.

The decision costs almost nothing. `convert` already reads the `time_series` column of every row. A
series must state how many values it holds before the writer asks for any of them. The finiteness
check runs over a buffer that this read has already decoded. The annotation adds the
check, not the read.

### The multivariate ratio the card claims does not hold — **Handled**

**Problem.** The card says multivariate and univariate examples were sampled at a 2:1 ratio. Across
the corpus it is 264,209 to 354,299, or **0.75 : 1** *(measured)*. The claimed ratio holds only
inside `ChatTS`, at 70,079 to 35,006.

**Decision.** Nothing to do in the conversion. Recorded because anyone who reproduces the
pretraining mix of SLIP needs it.

**Consequence.** None for the data.

### `state.json` names files the release does not ship — **Handled**

**Problem.** It lists 17 files named `data-000NN-of-00017.arrow`. The repository ships 17
`train-000NN-of-00017.parquet` files and no `.arrow` file. It is a leftover from
`datasets.save_to_disk`.

**Decision.** Ignore it. The connector reads the shards.

**Consequence.** None.

### `meta.csv` states a rate that a machine cannot read — **Handled**

**Problem.** The `Freq` column mixes several forms: a frequency (`65 Hz`), a period (`0.001 sec`,
`4 sec`), calendar words (`Hourly`, `Daily`, `30 min`), the same rate written two ways (`3h` and
`3 h`), and the null marker `-`.

**Decision.** Parse every form the table uses. The seven corpora whose cell holds `-` give an
`OrdinalAxis`, because the release states no rate for them. An empty cell reads the same way, and
this release has none. A form the table has not used stops the build, and so does a rate or a period
that TimeF cannot address.

**Consequence.** 484,001 records carry a real time axis and 134,507 do not *(measured)*. A model
that needs a wall-clock rate can select on it. If a later release adds a rate this connector cannot
read, the build fails and names the cell.

## Warnings this build emits

One line per kind, with the count and one example, through this module's logger. A property shared
by thousands of records is one fact about the release, not one fact per record. A kind that counts
nothing logs nothing, so the row below at zero is what a later release trips, not a line this build
prints.

| warning | how many it covers *(measured)* | why |
| --- | --- | --- |
| records hold a series with no finite numbers at all | 96 | one `dalia` series in each of those rows is entirely NaN |
| records hold a series with some values that are not finite numbers | 0 | no series of this release mixes finite numbers with non-finite ones |
| captions hold a paraphraser stub rather than text | 216 | the caption column holds `Paraphrase 1:` or similar |
| captions stop mid-sentence | 123,098 | the generator hit a length limit, and the text was cut there |

## What is not built

The 11 evaluation folders of the same repository. They hold fixed-length windows under a different
schema, so they are a different dataset with its own id.

The other columns of `meta.csv`: `Time Points`, `File Size`, `ADF`, `Forecast.`, `Description` and
`patch_size`. They are facts about the corpora SLIP drew from, not about any row.

The link between a row and the exact recording it was cut from. The release states the corpus a row
came from and nothing finer. A row cannot be traced back to a subject, a session or a file.
